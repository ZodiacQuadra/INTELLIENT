======== /three-enterprises  (Designed, Observed and Lived Enterprise | Intellient)
meta: Why documents, operational evidence and human experience must be reconciled before AI is built.
# Frame
  # Frame
    Operating reality
    [h1] The process you designed is not the only process you run.
    Every enterprise has an intended system, an evidenced system and a human system. Transformation fails when one is mistaken for the whole.
    # Frame row -> /air-audit
      Explore AIR Audit
# Frame
  # Frame
    [h2] Three forms of the same enterprise.
    # Frame
      # Frame
        [h4] The Designed Enterprise
        Policies define the control. Process maps define the path. The design makes scale possible, but cannot capture every exception.
      # Frame
        [h4] The Observed Enterprise
        Timestamps show the wait. Queues show the backlog. Evidence reveals patterns, but not always their cause.
      # Frame
        [h4] The Lived Enterprise
        People navigate workarounds, informal approvals and knowledge that never reached the process document.
# Frame
  # Frame
    # Frame
    Documentation tells us what should happen. Evidence shows what did happen. People help explain why.
# Frame
  # Frame
    A simple example
    [h2] The documented purchase request moves cleanly from submission to approval.
    Operational evidence shows requests returning repeatedly. People explain that approvals arrive without supporting evidence and a separate classification sheet is used. An agent that drafts the request may save minutes. A redesigned flow that assembles the evidence may remove days.
# Frame
  # Frame
    [h2] Make sure you know which process you mean.
    AIR Audit reconciles all three views into one future state.
